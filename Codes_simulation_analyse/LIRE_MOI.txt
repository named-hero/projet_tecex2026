CODES SEPARES - SIMULATION, ANALYSE, COMPARAISON

1. Simulation_formes.m : equipe, simulation uniquement
   Reprend main2(1).m, avec cercle, rectangle, trapeze et PNG.
   Meme affichage en millimetres, parula, impacts bleus, point fixe rouge.
   Les resultats sont enregistres dans resultats_simulation, avec horodatage.
   Aucun appel aux fichiers d'analyse. k-Wave doit etre correctement installe.
   calcul_simulation=false permet de verifier les geometries sans k-Wave.
   Les proprietes 3000 m/s et 2500 kg/m3 sont provisoires.
   Pour PNG blanc/transparent : png_matiere_sombre=false (reglage actuel).
   Pour PNG noir/blanc : true. Le PNG est importe directement.
   Ce script ne lit pas les fichiers shape de l'ancien importer_forme.m.
   Au changement de materiau, reutiliser le placement pour comparer les memes points.
   Un ancien placement ne contenant pas le masque doit etre recree (choisir Non).

2. Analyser_simulation.m : KEIRA, etape 4
   Mettre tous les fichiers .m de ce dossier ensemble.
   Ouvrir Analyser_simulation.m et cliquer Run.
   Choisir un ou plusieurs fichiers Sim_....mat (Ctrl+clic).
   Le script appelle resolution_contraste.m, sans relancer la simulation.
   Affiche les valeurs par impact, puis minimum, moyenne, maximum et ecart-type.
   Enregistre dans le sous-dossier analyses :
     Analyse_...mat : resultats complets pour l'etape 5 ;
     ..._impacts.csv : valeurs par impact ;
     ..._resume.csv : statistiques de chaque simulation.
   Refaire la meme analyse remplace ses fichiers de sortie, pas la simulation.

   Appel direct du calcul (sans sauvegarde automatique) :
     stats = resolution_contraste;
   Une boite permet de choisir le fichier.
   Ou :
     stats = resolution_contraste('chemin/Sim_exemple.mat');
     stats.resume
     stats.par_impact

3. Tableau_comparaison.m : KEIRA et CHADY, etape 5
   Dans la Command Window :
     comparaison = Tableau_comparaison;
   Choisir les fichiers Analyse_...mat de l'etape 4, pas les fichiers Sim.
   Choisir ensuite ou enregistrer le CSV comparatif.
   Une ligne PAR SIMULATION conserve les differents placements/essais.
   Le code ne choisit pas automatiquement une geometrie gagnante.

DEFINITIONS
- Rx, Ry [cm] : largeur du pic spatial au seuil 0.5 de correlation normalisee.
  Interpolation lineaire entre les points encadrant le seuil.
  Le pic est celui autour de l'impact de reference, pas un pic eloigne.
- Contraste principal : 1 / moyenne des correlations avec les N-1 autres impacts.
- Autre_max : plus grande correlation avec un autre impact. Faible est preferable.
- Correlation : maximum absolu sur tous les retards temporels, signaux normalises
  en energie, sans retrait de moyenne (convention des codes precedents).
- Le code conserve dans stats les courbes et un contraste de profil secondaire.
  Ce dernier depend du fond estime aux extremites ; il n'est pas le contraste
  principal des tableaux.
- La methode 'fond' est disponible explicitement comme deuxieme argument :
    stats = resolution_contraste('Sim_exemple.mat','fond');
  Son seuil est fond + (sommet-fond)/2. Elle donne d'autres resolutions.
  Aucune affirmation de conformite au manuel du professeur : manuel non fourni.
- Ecart-type avec diviseur N-1 : dispersion entre positions.
  Pas de std/sqrt(N) presente comme une incertitude : les positions choisies
  ne sont pas des repetitions independantes au meme endroit.
- NaN : deux passages au seuil non disponibles sur le profil mesure (bord,
  trou, profil trop court...). Le code n'invente pas de largeur.
  Statistiques calculees sur valeurs FINIES avec N_valides affiche.
  Un seul point valide donne un ecart-type NaN. Inf de contraste (fond nul)
  reste dans les valeurs individuelles mais est exclu des statistiques finies.
  Une comparaison incomplete peut etre biaisee : ne pas classer sur sa seule moyenne.
- Une petite largeur ne garantit pas une distance minimale entre deux notes.
- Le modele acoustique 2D ne represente pas les ondes de flexion d'une vraie plaque.

DONNEES NECESSAIRES DANS LE .MAT DE SIMULATION
sensor_data : [nombre de sondes x nombre d'echantillons temporels]
positions_sondes : [nombre de sondes x 2], indices MATLAB [i j]
impacts : [N x 2], indices MATLAB [i j], N >= 2
indices_impacts : correspondance aux lignes des signaux (recalculee si absente)
dx, dy : pas spatiaux en metres
indices_profils_x, indices_profils_y : cellules N x 1, indices des sondes
  auxiliaires de chaque profil (recommandes ; enregistres par Simulation_formes).
Sans ces cellules : recherche de points contigus alignes, etendues_profils
  ou +/-6 pas par defaut. Aucun saut de trou ou d'echantillon manquant.
nom_forme, materiau.nom, materiau.sound_speed, materiau.density : identification.
Un fichier contenant seulement shape n'est pas un resultat de simulation.
Les positions finales ne sont pas necessaires pour preparer le calcul.

PROBLEMES TROUVES DANS LES FICHIERS DU COEQUIPIER
main(1).m utilise pathStr avant definition, charge une cellule sans accolades,
attend obj.impacts que importer_forme ne sauvegarde pas, ne definit pas matiere
pour le cas custom et n'enregistre pas correctement indices_impacts.
La largeur de redimensionnement Nx est egalement trop grande pour Ny=60.
importer_forme peut produire un tableau RGB 3D plutot qu'un masque logique 2D.
Le nouveau Simulation_formes utilise l'import PNG de main2, deja adapte,
plutot que cette branche incomplete. Il n'est pas necessaire d'executer importer_forme.

VALIDATION
Verification de la separation des appels et des contrats de donnees.
Pas d'execution MATLAB/k-Wave ici : MATLAB n'est pas disponible dans cet environnement.
